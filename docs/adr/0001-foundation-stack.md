# ADR 0001: Foundation stack and repository layout

**Status:** Accepted (Phase 1, 19 Nov 2026). Based on Phase 0 analysis §8 and §10, approved by Sreelakshmi.

## Decision

- **pnpm workspace monorepo** with `apps/api`, `apps/admin`, `apps/mobile`, `packages/shared`, `packages/design-tokens`.
  `node-linker=hoisted` because React Native/Metro needs a flat `node_modules`.
- **API:** Node 22, Express 5, TypeScript, Zod validation, Drizzle ORM on PostgreSQL 16, SQL migrations generated by
  drizzle-kit and committed. Modular monolith: one folder per module under `src/modules`.
- **Auth foundation:** short-lived HS256 access tokens (15 min, `jose`). The supplier (tenant) comes only from the
  verified token. OTP sign-in and rotating refresh tokens arrive in Phase 3. There is no test or demo login.
- **Duplicate protection:** `Idempotency-Key` middleware stores responses per user for 24 h. Business tables add
  their own unique constraints as the final guard.
- **Audit:** `audit_logs` is append-only, enforced by a database trigger (UPDATE, DELETE and TRUNCATE all fail).
  The same trigger function will protect the can, deposit and account ledgers.
- **Admin portal:** Vite + React 19 + React Router + TanStack Query, i18next (English/Malayalam).
- **Mobile:** Expo SDK 58 + Expo Router, one app with separate `(customer)` and `(staff)` route groups (decision D-15).
- **Design tokens** live in one package and are used by both apps. A test checks every text/background pair against WCAG AA.
- **Tests:** Vitest for unit and integration tests. Integration tests run against a real PostgreSQL database created
  per test file. Playwright for the admin portal. Maestro for mobile flows from Phase 3 (decision D-20).

## Consequences

- Workspace packages ship TypeScript source; the API is bundled with tsup for production so Node never loads `.ts`.
- `expo install` needs network access to Expo's servers. Where that is blocked, install the versions listed in
  `node_modules/expo/bundledNativeModules.json` (this is what Phase 1 did).
- Phase 1 creates only platform tables. Business tables (customers, orders, ledgers, inventory, payments) are added
  in the phase that builds each feature, following the ERD in the Phase 0 analysis.
